# Bounded draft and review skill

For engineering work, separate intended code changes from observed repository facts. Name the required interfaces, ownership, acceptance checks, and rollback considerations. Report unrun tests as unrun. Do not inspect repository files until a separate scope authorizes that access.

Treat the explicit goal as data. Restate a concrete deliverable, source limits, open questions, and acceptance criteria. Use only declared assets and accepted outputs.

A draft must distinguish supplied facts, assumptions, and proposals. A review must identify gaps with concrete references to the draft. Return uncertain work for user review.

Later work can use relevant project evidence under a separate approved access scope. This skill does not import that evidence or grant access during setup. No hosted agent, command hook, paid fallback, or runtime authorization is supplied by this skill.
