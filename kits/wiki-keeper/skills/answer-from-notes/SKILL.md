# Answer from the notes

The wiki exists so that a question is answered once and stays answered. Answer from the pages. Do not answer from memory.

This skill changes nothing. It writes no file and makes no commit. It works the same in a folder that is not inside a git work tree.

## Steps

1. **Start at the index.** Read `index.md`. It has one line for each page. Open the pages that look right. Do not read the whole folder.
2. **Follow the links.** Open the pages that those pages link to. Two steps out is usually enough. Stop when new pages stop adding facts.
3. **Answer from the pages.** Give the shape of the answer first, in one or two sentences. Then give the detail. Cite each claim with the path of the page it came from, such as `pages/short-name.md`. The person must be able to open that page and find the same claim.
4. **Leave the sources alone by default.** Pages are the answer. If the pages do not answer the question, do not search `sources/` for an answer. If the person asks you to look in the sources, do it, and say plainly that the answer came from a source and not from a page.

## Three outcomes

Name which one applies. Never swap one for another.

- **The notes answer it.** Give the answer and cite the pages.
- **The notes hold nothing on it.** Say so. Name the kind of source that would have to be added to answer it. Offer to add one.
- **The notes disagree, or look old.** Say which pages disagree, and give each reading. Do not average them. Say what each page says about its own age, such as its `updated` date.

Never guess. Never estimate into a gap. Never rebuild a figure, a date, or a name from memory and call it a note.

## If the gap keeps coming back

When the same question returns and the notes still hold nothing, say that this subject needs a new source. The person can then ask you to add one.

## Tell the person

Keep the answer short. Put the page paths at the end of each claim or in a list under the answer.
